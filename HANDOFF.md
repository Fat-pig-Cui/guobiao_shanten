# Guobiao Shanten Analysis Handoff

## 1. Scope

This repository is a standalone working copy of the Guobiao Mahjong shanten
analysis originally kept in:

`/Users/chubbypig/Library/CloudStorage/OneDrive-个人/archive/雀魂相关/各种情况下的大数据分析/向听数分析/国标麻将/`

That source directory was not edited and still contains the old, incorrect
special-route tables.

## 2. Status

The five-route joint distribution is complete and exact for `N=14..37`.
Base routes guarantee a win for `N>=38` and all five routes for `N>=37`, so
no larger `N` needs to be computed.

- `joint_distribution.txt`: five-route joint weights.
- `base_distribution.txt`, `all_not_connected_distribution.txt`,
  `combo_dragon_distribution.txt`: single-route marginal weights, from the
  same engine with one route enabled.
- `base_anc_distribution.txt`, `base_combo_distribution.txt`: base routes
  plus one special route, for the route comparison.
- `report_template.md`: report text with one `{{table:NAME}}` line per table.
- `report.md`: generated by
  `python3 make_report_tables.py --render report_template.md report.md`;
  it contains no marker syntax.

## 3. Corrections made to the earlier version

- `compute_all_not_connected.cpp` sorted the three 12-bit group fields after
  each convolution. Those fields hold per-suit data, so sorting mixed
  suits. About 47% of random deals got a wrong value. The sort was removed,
  and the range is limited to `N<=54` (`unsigned __int128`); the default is
  37. The old `N=55..81` rows had also overflowed.
- `compute_combo_dragon.cpp` canonicalised states over suit permutations,
  but per-suit summaries depend on the suit, so permuted states are not
  equivalent. About 28% of random deals got a wrong value. The
  canonicalisation was removed; the program now takes a maximum `N`
  (default 16) because its state space is large.
- The old baseline table counted seven pairs as seven distinct types. The
  new baseline uses the Guobiao rule (four of a kind counts as two pairs),
  matching `compute_n14_tianhe.cpp`.

- `sample_best14.cpp` added the thirteen-orphans terminal count `u` to the
  all-not-connected value, so number terminals in the skeleton were counted
  twice (for `147m258p369s11223z` it gave -1 instead of 1). It now counts
  only honour types. The sampler is still diagnostic only because its
  combination-dragon value is approximate.

## 4. Method

`guobiao_engine.hpp` computes, for each threshold `t`, the weight `A_N(t)` of
deals whose value on every enabled route is still greater than `t`. Then
`W_N(r) = A_N(r-1) - A_N(r)`. Main points:

- Route values only improve when tiles are added, so partial deals that
  reach `t` on any route are dropped.
- Special-route overlaps that cannot reach `13-t` with the remaining blocks
  are clamped to zero.
- Suit summaries are suit-independent: all-not-connected and combination
  dragon values are indexed by position group `g` (tiles `g, g+3, g+6`).
  After two suits, values are indexed by the group left for the third suit.
- Two suits are paired unordered, and states are merged under the mirror
  `i -> 8-i` (group 0 <-> 2). The honour block is only used in the final
  check.

Peak sizes for `N<=37`: suit 26,771 states, pair 314,280, triple 31,748.
The full run takes about 65 s and 140 MB on Apple M4 (10 cores).

## 5. Validation

`./test_joint` must print `ALL PASSED`. It checks:

- randomised per-deal agreement with direct target enumeration for all
  routes and for each single route;
- total weight `C(136,N)` for `N=14..16`;
- the `N=14` five-route winning weight `13,257,769,189,488`;
- the base-only distribution against the `shanten_core.hpp` convolution.

`compute_joint` also checks every output row against `C(136,N)` and accepts
`max_n` up to 54. `choose_u128` divides out a common factor before each
multiplication, so it is exact whenever the result fits in 128 bits and
throws otherwise (the old version overflowed from `C(136,47)`). The
single-route outputs match the independent calculators exactly
(all-not-connected for `N=14..37`, combination dragon for `N=14..16`).

## 6. Possible extensions

- Other rule variants (for example a different seven-pairs rule) only need
  changes in `suit_summary`, `honour_summary`, and the base checks in
  `dead` and `final_alive`.

## 7. Notes for editing the report

- Markdown formulas should define symbols in prose and contain no Chinese
  text; table columns should remain centered with `:---:`.
- Edit `report_template.md`, then regenerate `report.md` with
  `python3 make_report_tables.py --render report_template.md report.md`
  rather than editing numbers by hand. Tables with eight or more columns
  are split by column; values below 0.001 use a compact exponent such as
  `2.593e-4%`, and values above 99.99% are written `>99.99%`. Numbers quoted in the prose (summary
  and sections 3 and 4) must be updated manually if the data change.
